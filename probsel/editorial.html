Subtask 2 (strictly increasing or decreasing) (17 points)

Hint 1
For a strictly increasing array, which value remains in the final stack? What changes when a position is removed?
Hint 2
For a strictly decreasing array, which values remain? What changes when a position is removed?
Solution
Time: | Space:

If the values are strictly increasing, each new value removes everything before it. So removing any position except the last leaves only the last value. Removing the last leaves the second-to-last value.

If the values are strictly decreasing, no element is ever popped. The answer for removing position is the total minus .

Compare the first and last values to find the direction. For = 1, the answer is zero.

        ans[n-1] = a[n-2];
    }
    else for (int i = 0; i < n; i++) ans[i] = sum-a[i];

Solution 2
Hint 1
Without simulating the stack, is there a rule for whether a value survives?
Solution
Time: | Space:

Notice that a value stays in the final stack exactly when every value to its right is smaller. So whether it stays depends only on later values. This suggests scanning from right to left: when we reach a value, we have already seen everything that could block it.

Call a later element a blocker if its value is at least as large as the current one. After one deletion, a value can survive only if it has no blockers, or if it has one blocker and that blocker is deleted. With two or more blockers, removing one position cannot help.

Start with the sum of all values that have no blockers. For each value with no blockers, subtract it from the answer at its own position. For a value with exactly one blocker, add it to the answer at that blocker’s position. Values with two or more blockers can be ignored. Then add the common sum to every answer.

For each value, scan to its right and count up to two blockers. This gives O(N2) time and O(N) space, including the answers. The faster reverse-processing methods use the same blocker idea.

#include <bits/stdc++.h>
using namespace std;

const int N = 10000005;
int n, a[N];
long long ans[N], sum;

... // [template]

int main() {
    ... // [input]

    for (int i = 0; i < n; i++) {
        int cnt = 0, removed = -1;
        for (int j = i+1; j < n && cnt < 2; j++) {
            if (a[j] >= a[i]) {
                cnt++;
                removed = j;
            }
        }

        if (cnt == 0) {
            sum += a[i];
            ans[i] -= a[i];
        }
        else if (cnt == 1) ans[removed] += a[i];
    }

    for (int i = 0; i < n; i++) ans[i] += sum;

    ... // [output]
}

Subtask 3 () (19 points)

Solution 1
Hint 1
Do we actually need to simulate removing every position?
Hint 2
For the positions that matter, can we start from the sum with no removal?
Hint 3
Can we reduce the part that needs to be simulated?
Solution
Time: | Space:

Notice that pushing a new value can remove earlier values from the stack, but cannot bring them back. This suggests that deleting a value can only bring back values that were removed before. Instead of simulating the whole array after every deletion, we can find which values might return.

First, simulate the original array once and keep its final stack. If a value is not in this stack, we can ignore its deletion: a value at least as large still lies to its right, so the final stack will not change. So we only need to check positions in the original final stack.

Consider deleting the -th surviving element, . The original final stack is strictly decreasing, so the previous survivor has a larger value. Every value removed by is at most , so it is smaller than . Even if these values could return when is deleted, the previous survivor would still remove any of them that appear before it. So nothing before can change.

Removing does not change which values to its right survive, because their survival depends only on later values. So only values between and can be added, or values from the start of the array when .

Start each answer from the sum of the original final stack and subtract the deleted survivor. We only need to simulate that interval. If there is a next survivor, skip values that are at most that survivor: they would still be removed later. Run the stack process on the remaining values with a temporary stack. Add each pushed value and subtract each popped value from the answer.

The intervals between surviving values do not overlap. Across all deletions, each original position belongs to at most one such interval. Each value is pushed and popped at most once. Including the first stack construction, the total time is .

#include <bits/stdc++.h>
using namespace std;

const int N = 10000005;
int n, a[N], st1[N], st2[N];
long long ans[N], sum;
int sz1, sz2;

... // [template]

int main() {
    ... // [input]

    for (int i = 0; i < n; i++) {
        while (sz1 && a[i] >= a[st1[sz1-1]]) sum -= a[st1[--sz1]];
        st1[sz1++] = i;
        sum += a[i];
    }

    for (int i = 0; i < n; i++) ans[i] = sum;


    for (int i = 0; i < sz1; i++) {
        int removed = st1[i];
        ans[removed] -= a[removed];

        sz2 = 0;
        int l = i ? st1[i-1]+1 : 0;
        for (int j = l; j < removed; j++) {
            if (i == sz1-1 || a[j] > a[st1[i+1]]) {
                while (sz2 && a[j] >= a[st2[sz2-1]]) ans[removed] -= a[st2[--sz2]];
                st2[sz2++] = j;
                ans[removed] += a[j];
            }
        }
    }

}
Solution 2
Hint 1
Each element needs information about the elements to its right. How should we change the iteration order to make that information available?
Hint 2
Can we find the blockers of the current value faster?
Solution
Time: | Space:

The array-based reverse scan checks blockers for each position. After finding two, we can stop: deleting one position cannot remove both blockers. We only need to know whether there are zero, one, or at least two blockers.

We now need to find the blocker count without scanning all later values. Keep an ordered set of later values that can still matter. If a value already has two blockers in the set, we can ignore it. Any earlier value blocked by it is also blocked by those two values. So ignoring it does not change whether an earlier value has zero, one, or at least two blockers.

Store each kept value with its position. Use lower_bound to find the first value in the set that is at least the current value. If no such element exists, there are zero blockers. If it is the last element in the set, there is exactly one blocker; otherwise there are at least two. For zero blockers, update the common sum and subtract the value from its own adjustment. For one blocker, add the value to that blocker’s adjustment. For two or more, skip the value entirely.

Insert only values with fewer than two blockers. Each iteration performs at most one search and one insertion, giving O(NlogN) time and O(N) space.

#include <bits/stdc++.h>
using namespace std;

const int N = 10000005;
int n, a[N];
long long ans[N], sum;
set<pair<int, int>> s;

... // [template]

int main() {
    ... // [input]

    for (int i = n-1; i >= 0; i--) {
        auto it = s.lower_bound({a[i], -1});
        if (it == s.end()) {
            ans[i] -= a[i];
            sum += a[i];
        }
        else {
            auto it2 = next(it);
            if (it2 != s.end()) continue;
            auto [value, removed] = *it;
            ans[removed] += a[i];
        }
        s.insert({a[i], i});
    }


    for (int i = 0; i < n; i++) ans[i] += sum;

    ... // [output]
}

Subtask 4 (no additional constraints) (16 points)

Solution 1
Solution

Solution 2
Hint 1
Which later values do you actually need to keep?
Solution
Time: | Space:

We used the ordered set only to tell whether a value has zero, one, or at least two blockers. A blocker is any later value that is at least the current value. So the two largest later values are enough to tell which case applies. We no longer need the set.

Maintain mx1 and mx2, the largest and second-largest values to the right, even if the two values are equal. Also store p, the position of the largest value. For the current value x, if x>mx1, no blocker exists: add x to the common sum and subtract it from the adjustment at its own position. Otherwise, if x>mx2, exactly one blocker exists, at p: add x to that position’s adjustment. Otherwise, there are at least two blockers, so x cannot survive after any single deletion.

Update the two maxima only after processing the current value. This way, they describe only later positions when we check for blockers. Reuse the input array for adjustments, then set each ansi to the common sum plus the adjustment. The scan takes O(N) time with O(N) total storage for the input and answers, and O(1) auxiliary state beyond them.

#include <bits/stdc++.h>
using namespace std;

const int N = 10000005;
int n, p;
long long a[N], ans[N], sum, mx1 = -1, mx2 = -1;

... // [template]

int main() {
    ... // [input]

    for (int i = n-1; i >= 0; i--) {
        long long x = a[i];
        a[i] = 0;

        if (x > mx1) {
            sum += x;
            a[i] -= x;
        }
        else if (x > mx2) a[p] += x;

        if (x > mx1) {
            mx2 = mx1;
            mx1 = x;
            p = i;
        }
        else if (x > mx2) mx2 = x;
    }


    for (int i = 0; i < n; i++) ans[i] = sum+a[i];

    ... // [output]
}
